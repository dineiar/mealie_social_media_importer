I want you to draw the UI for a web/mobile site that I will create to import recipes from various social media into Mealie (an existing recipe management system).
The site should be very clean and simple. It will feature a single field to paste a Mealie API key that will work as a login and an option to "Remember me" (on by default), which stores the key in the browser's cache. Upon providing the API key, the website checks if the key is valid by fetching the user's information from the Mealie API and displays that username and an option to logoff (effectively forget the Mealie API key stored in the browser).
After logging in, the user should be presented with a single field to paste a URL from a social media website to import the recipe into Mealie. The website then will download the media from the social media (post, image, video) and send it to Mealie for parsing with AI. If Mealie is unable to extract a recipe from the post's text, the system will extract the audio from the video, transcribe it, and use it to import the recipe. After creating the recipe on Mealie, the system imports the media (image or video) as an attachment in Mealie.
If the import fails (e.g., Mealie is offline or unable to extract the recipe), the user should be presented the option to download the extracted media (image/video/text) so they can create the recipe manually and attach the media themselves. The imported URLs and media will be stored temporarily in the server's storage to enable the download, and automatically erased after a short period, so the system should not store a permanent list of imported URLs, but only those that the user imported recently and are still available to download.
The import page should also display which social media/websites are supported and available for importing from, and which social media are technically supported but not configured yet (authentication is not configured, for example).

So, in summary, the system should have 2 simple pages: login with API key and import+recently imported media.
